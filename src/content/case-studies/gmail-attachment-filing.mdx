## About this build

Built on Make for **Fernhill Bookkeeping, a fictional sample client** that receives receipts, statements and scans from its clients by email. The scenario itself is real and complete, and has filed real attachments end to end.

## The problem

- **Filing by hand.** Every attachment was downloaded and saved one at a time.
- **Names that say nothing.** Files like scan001.pdf had to be opened to find out what they were.
- **No record.** Nobody could say what had arrived, from whom, or where it was saved.
- **Silence for the client.** Senders never knew whether their documents had been received.

## What I built

1. **Find new attachments.** Every 15 minutes, Gmail is checked for emails labelled To File that have attachments, up to 10 emails per run.
2. **Keep real attachments.** Each attachment is listed, and only real files go on: no Office documents, no empty parts, and nothing 20 KB or smaller, such as signature logos.
3. **Name it with AI.** Each file is uploaded to Gemini, which reads it and returns a short, descriptive name, keeping the original extension.
4. **File and log.** The file is saved to the client documents folder in Google Drive, and a row is added to the Google Sheets log with the date, original name, new name, file type and link.
5. **Confirm once.** The new names from that email are gathered into one list, and the sender gets a single receipt showing each file as its new name, sent as the old one.

## Safeguards

- **Original extension kept,** so a PDF stays a PDF whatever Gemini calls it.
- **Retries on failure:** a failed Gemini or Drive step is retried up to 3 times, 15 minutes apart.
- **One receipt, only when something was saved,** never one per file and never an empty one.
- **Inbox untouched:** emails are not marked as read or moved.

## Outcomes

- Every attachment is saved under a name that says what it is.
- A running log shows what arrived, when, and where it went.
- Clients get confirmation that their documents arrived.
